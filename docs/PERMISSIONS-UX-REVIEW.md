## Guest ដោយមិន Login

- ចុច «ចូលជា Guest ដោយមិន Login» នៅផ្ទាំង Login។
- មើល Dashboard និង Booking details គ្រប់ផ្នែកបាន។
- មើលឈ្មោះ អ្នកសម្របសម្រួល លេខទូរស័ព្ទ បន្ទប់ ផ្នែក អ្នកចូលរួម សម្ភារៈ និងកំណត់ចំណាំបាន ព្រោះ Owner បានជ្រើសឱ្យព័ត៌មានទាំងនេះជាសាធារណៈ។
- មិនអាចមើល Reports, Calendar popup, Calendar Sync, User Control ឬ Inventory បាន។
- មិនអាចបើក Form ស្នើសុំពី Dashboard កែ ឬលុបចោល Booking បាន។ Public Form នៅតែដំណើរការសម្រាប់អ្នកដែលមាន Link ផ្ទាល់។
- API សាធារណៈមិនបញ្ជូន Google Calendar ID, Telegram ID, Request ID និងកំហុសបច្ចេកទេស។
- ប៊ូតុង «ចូលគណនី Google» ចាកចេញពី Guest mode និងត្រឡប់ទៅ Login។

## ចំណុចរកឃើញ និងការកែ

1. **Login → Form**: តំណប្រើ client-side navigation របស់ framework ដែលមានបញ្ហាក្នុងការប្តូរទំព័រ។ ប្តូរទៅ native HTML link ដើម្បីបើក Form នៅក្នុង tab ដដែល។ មិនតម្រូវឱ្យបើក New Tab។
2. **ការកែអ្នកប្រើជាប់ក្នុងបញ្ជី**: ពិបាកបំបែកការមើលពីការកែ។ បញ្ជីថ្មីបង្ហាញឈ្មោះ Email តួនាទី ស្ថានភាព និងអ្នកកែចុងក្រោយ។ ការកែបើកក្នុងផ្ទាំងដាច់ដោយឡែក។
3. **ផលប៉ះពាល់សិទ្ធិមិនច្បាស់**: បន្ថែមតារាងសិទ្ធិ និងការពន្យល់តាមតួនាទីពេលជ្រើស។ Viewer រួមមានការទាញយករបាយការណ៍ និងការមើលព័ត៌មានគ្រប់ផ្នែក។
4. **មិនទាន់មានការពិនិត្យការផ្លាស់ប្តូរ**: មុន Save បង្ហាញគណនីគោលដៅ តួនាទីចាស់/ថ្មី និងស្ថានភាព។ បិទ/បើកអ្នកប្រើក៏ត្រូវឆ្លងកាត់ការពិនិត្យនេះ។
5. **ការបាត់ការកែដោយចុចបិទ**: បង្ហាញការបញ្ជាក់បោះបង់ពេលមានការកែដែលមិនទាន់ Save។
6. **គណនីស្ទួន**: Email ត្រូវបានផ្ទៀងផ្ទាត់ និងពិនិត្យគណនីមានស្រាប់នៅ UI។ Backend នៅតែបដិសេធការបន្ថែមស្ទួន។
7. **Owner មិនអាចកែបាន ប៉ុន្តែមិនមានការពន្យល់**: បន្ថែមផ្ទាំងមើលសិទ្ធិ Owner និងពន្យល់ពីការការពារកុំឱ្យបាត់សិទ្ធិគ្រប់គ្រង។
8. **ការស្វែងរក**: បន្ថែមតម្រងតួនាទី ស្ថានភាព និងចំនួនលទ្ធផល; ក្រោយ Save សម្អាតតម្រងដើម្បីឱ្យឃើញគណនីដែលបានកែ។
9. **ការផ្តល់ Link**: បន្ថែមចម្លងតំណ Login និងបញ្ជាក់ថាមិនមាន Email អញ្ជើញផ្ញើដោយស្វ័យប្រវត្តិ។
10. **សិទ្ធិក្រោយ Login**: Backend ពិនិត្យសិទ្ធិនៅរាល់សំណើ។ UI ពិនិត្យឡើងវិញពេល API ឆ្លើយ 403 និងរៀងរាល់ ១ នាទី។ គណនីបានបិទបង្ហាញសារច្បាស់; service outage ត្រូវបានបំបែកពីការបដិសេធសិទ្ធិ។
11. **WebMCP**: Viewer មិនចុះឈ្មោះ mutation tools នៅក្នុង browser។ Backend នៅតែជាចំណុចអនុវត្តសិទ្ធិ និងមិនពឹងការលាក់ប៊ូតុងទេ។
12. **Default deny**: Permission ដែលមិនស្គាល់ត្រូវបានបដិសេធ។

## អ្វីដែលមិនទាន់មាន

- Username/Password និង Password Reset: បច្ចុប្បន្ន Login តាម Google។
- Custom permission ជាប៊ូតុងដាច់ៗ (ឧ. Editor អាចកែ តែមិនអាច Cancel): បច្ចុប្បន្នប្រើតួនាទី ៣ ខាងលើ។
- ប្រវត្តិ Login និងប្រវត្តិកែសិទ្ធិពេញលេញនៅ UI: បង្ហាញតែការកែសិទ្ធិចុងក្រោយ។ មិនបង្កើតតម្លៃ last-login ដែលមិនមានទិន្នន័យពិត។
- ការទប់ការកែជាន់គ្នារវាង Admin ច្រើនក្នុងពេលតែមួយមិនទាន់មាន transaction-level protection; Google Sheets ប្រើ append-order សម្រាប់សិទ្ធិចុងក្រោយ។

## មូលដ្ឋាននៃការពិនិត្យ

- [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html): least privilege, deny by default និងពិនិត្យសិទ្ធិគ្រប់សំណើ។
- [W3C Form Notifications](https://www.w3.org/WAI/tutorials/forms/notifications/): សារ error/success ត្រូវច្បាស់ និងប្រាប់ផ្លូវដោះស្រាយ។
- [W3C Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): keyboard focus, Escape និងការត្រឡប់ focus។

នេះជាការពិនិត្យលើ flow និងសិទ្ធិជាក់លាក់ មិនមែនការធានាថាប្រព័ន្ធទាំងមូលបានឆ្លង security audit ឬ WCAG certification ទេ។
